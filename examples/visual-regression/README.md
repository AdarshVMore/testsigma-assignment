# Visual regression example

Demo requirement #2: two screenshots where visual regression detects and
highlights a real change.

`before.png` / `after.png` are a small mock "login card" UI generated by
`generate_fixtures.py`. Between the two, the primary button's color and
label change ("Log In" blue → "Sign In" near-black) — everything else on the
card is pixel-identical.

## Reproduce

```bash
cd packages/visual-regression
.venv/bin/python ../../examples/visual-regression/generate_fixtures.py
.venv/bin/python src/cli.py \
  ../../examples/visual-regression/before.png \
  ../../examples/visual-regression/after.png \
  --output-dir ../../examples/visual-regression/output
```

Exit code is `1` (regression detected) — that's expected here, not an error.

## What's in `output/`

- `result.json` — machine-readable result: `passed: false`, `diffPercentage`, and one `regions` entry whose bounding box tightly matches the button.
- `diff.png` — grayscale heatmap: white = changed pixels, black = unchanged. Only the button area is white.
- `highlighted.png` — the after-screenshot with a red box drawn around the detected region.

## A note on the color choice

An earlier version of this fixture changed the button from blue `(66,133,244)`
to green `(52,168,83)` — and the tool reported **no** difference. That
wasn't a bug in the fixture generator; it's the grayscale-luminance
blind spot documented in the main README's "V1 limitations": blue and that
particular green convert to almost identical grayscale luminance (~126 vs
~124), so a purely luminance-based diff can't see the change. Left as-is
here rather than quietly picked around, because it's a genuine, real
limitation worth being able to point to.
